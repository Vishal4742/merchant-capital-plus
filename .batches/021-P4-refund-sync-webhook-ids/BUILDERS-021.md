## Builder R: `POST /api/v1/payments/{id}/refunds/sync`
Files: `apps/web/lib/server/refunds.ts`, `apps/web/app/api/v1/payments/[id]/refunds/sync/route.ts`, `apps/web/test/gw-refunds.test.mjs`.
- Read first: `lib/sessions.ts` (`listPayments(merchant)` → `{session, payment}[]`; `payment.paymentId` (string), `payment.amount` (bigint, the charged price)), `lib/config.ts` (`payConfig()` → `{merchantPay}`), `lib/onchain.ts` (how it builds the viem client: chain, transport, timeouts; `readTxFee` shows an injectable receipt reader), `lib/server/events.ts` (`onRefund(session, amount, totalRefunded, paidAmount)`: it already sends once per `refund:<session>:<total>`), `lib/server/http.ts` (`handle`, `HttpError`, `signedInMerchant`, `readJson`), `lib/server/reports.ts` (the Refunded event ABI + how it decodes logs, incl. the viem decodeEventLog eventName check).
- `syncRefund(merchant, paymentId: bigint, txHash: Hex, { readReceipt } = {})`: 404 unless `listPayments(merchant)` has that paymentId; read the receipt (`readReceipt(txHash)`, default: a viem public client like onchain.ts's); `status !== "success"` → 400 "That refund transaction failed."; keep logs whose `address` equals `payConfig().merchantPay` (case-insensitive), topic0 = the Refunded selector, `paymentId` = this one (decode, and check the decoded eventName); none → 400 "That transaction has no refund for this payment."; for each matching log (normally one), `await onRefund(session, amount, totalRefunded, payment.amount)`; return `{payment_id, refunds: [{amount, total_refunded}], tx_hash}` (amounts as decimal USDT strings). 503 if `payConfig()` is missing.
- Route: dashboard cookie (`signedInMerchant`), body `{tx_hash}` (`isHash`, else 400), `id` a decimal integer (else 400), rate limit `refunds:<merchant>` 30/min.
- Tests (mock `readReceipt` and `onRefund` via `mock.module("../lib/server/events.ts", …)`; a session + payment via `createSession` + `recordPayment` from lib/sessions.ts): the good path calls onRefund once with the right numbers; a log from another address or another paymentId is ignored → 400; a reverted receipt → 400; an unknown payment / another merchant's → 404; no cookie → 401; a bad tx hash or id → 400; payConfig missing → 503.
