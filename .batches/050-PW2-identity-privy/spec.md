## Design (deltas from 032; everything else as frozen there)
**Login (FR-BIZ-6 v3.1).** `/sign-in` (the only page that loads Privy; CSP allows auth.privy.io + WalletConnect like the pay sheet) → Privy `login()` with `loginMethods: ["email","wallet"]`, `embeddedWallets.ethereum.createOnLogin: "off"`, chain 1874 → `POST /api/v2/auth/privy` with `Authorization: Bearer <access token>` and `{ idToken }`. Server (`lib/server/privy-token.ts`, node:crypto only, no new dependency): JWS compact, header `alg` must be exactly `ES256`, signature P1363 over `header.payload` with `PRIVY_VERIFICATION_KEY` (public SPKI PEM from the Privy dashboard); claims `iss === "privy.io"`, `aud === NEXT_PUBLIC_PRIVY_APP_ID`, `exp > now - 30 s`, `iat ≤ now + 30 s`, `sub` matches `did:privy:…`; ≤ 4 KB. Identity token: same checks + `sub` equal to the access token's; `linked_accounts` parsed **defensively** (JSON string → array; `type: "email"` + `address`; `type: "wallet"` + 0x address, `chain_type` absent or `ethereum`, `wallet_client_type !== "privy"`). Unknown shapes yield no wallets (fail closed). Config missing → 503 "Sign-in isn't set up on this server". Then: principal upsert by `privy_did`, wallet set replaced, session insert — one CTE. Session = opaque 32-byte token, sha256 stored, `wf_session` HttpOnly SameSite=Lax Path=/ Secure on https, 8 h, revocable. Same-origin required (Origin = PUBLIC_ORIGIN or Sec-Fetch-Site same-origin) on every cookie-authenticated unsafe method incl. sign-in/out. Audited.
**Step-up (FR-BIZ-4).** Owner approval = fresh (≤ 5 min) purpose-bound EIP-191 signature by a wallet in the actor's `wf_principal_wallets` (Privy-verified at sign-in), never the session alone. Email-only Owners link a wallet in the Privy dialog and sign in again; the UI says so.
**Receiving proof (FR-BIZ-3).** EIP-4361 text built by the server (domain/URI from PUBLIC_ORIGIN; statement names purpose, business, token, network; Resources carry business id + policy hash; Chain ID 1874; 10-min expiry), signed by the recipient EOA (ecrecover only; EIP-1271 unsupported). Token fixed to the registry's Whitechain test USDT `0xcedfB56113143d55b2358b8CFbB0dEB5Ad2f55a7` (packages/shared). Proof ≠ approval: separate challenges and purposes, both consumed in the activation statement.
**CON-11.** At activation, `advanceOf(recipient)` is read on V1 CapitalMarket (the only obligation read the web app has); a failed read → 503 (fail closed); the result is stored on the policy row (`v1_obligations`) for V2 routes to refuse later; V1 collection unchanged.
