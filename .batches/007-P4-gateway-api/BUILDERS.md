## Foundation you use (already written; read them)
- `apps/web/lib/server/db.ts`: `query<T>(text, params)`. **House rules:** merchant addresses stored lowercase; times are `BIGINT` unix ms; money is `BIGINT` USDT units (6 decimals); always `SELECT col::text` for BIGINT and convert with `BigInt()` / `Number()`. No `timestamptz`, no `numeric`. Ids: `newId("lnk")` etc.
- `apps/web/lib/server/http.ts`: `handle(async () => …)` wraps every route body; throw `new HttpError(status, message)` for client errors; `ok(body, status?)`, `fail()`; `signedInMerchant(request)` (dashboard auth, 401); `readJson(request)`; `usdtField` (decimal string, 1..1,000 USDT → bigint units); `textField`, `currencyField`, `httpsUrl`, `futureTime`; `merchantName(address)`; `newId`, `newSlug`; `rateLimit(key, limit, windowMs)`, `clientIp(request)`; `MIN_PAYMENT`, `MAX_PAYMENT`, `CURRENCIES`.
- `apps/web/lib/server/checkouts.ts`: `recordCheckout(sessionId, kind, refId, merchant, usdtAmount)`, `checkoutOf(sessionId)`, `markCheckoutPaid(sessionId)` (true only the first time), `paidCounts(kind, refIds)`.
- `apps/web/lib/server/quotes.ts` (the lane writes it now): `createQuote(amount: string, currency: Currency): Promise<Quote>` with `Quote = {id, currency, amount, usdtAmount: bigint, rate: string, source: string, fetchedAt: number, expiresAt: number}`; `getQuote(id): Promise<Quote | null>` (null once expired). USDT and USD are 1:1.
- Existing app code you may import (don't edit): `lib/sessions.ts` `createSession({merchant, merchantName, amount, reference, items})` → `Session` (`id`); `lib/usdt.ts` `formatUsdt(units)` (gives "1,234.56"; for API JSON use `formatUnits(units, 6)` from viem: "1234.56"), `USDT`, `EXPLORER`; `lib/onchain.ts` `paidLogs(merchantPay, {merchant})`; `lib/config.ts` `payConfig()`; `lib/arkiv.ts` `arkivClients()`, `redactArkivError()`.
- Tests: `apps/web/test/gw-helpers.mjs`: `await setupDb()` once per file, `await resetDb()` in `beforeEach`, `signedIn(merchant?)` → cookie headers, `req(method, path, {body, headers})`, `params({id})` for dynamic routes, `MERCHANT`, `OTHER_MERCHANT`. Import route handlers directly (`import { POST } from "../app/api/v1/links/route.ts"`) and call them. Look at `test/checkout-api.test.mjs` for the house test style. Mock `fetch` with `mock.method(globalThis, "fetch", …)` (never hit the network).
- Route files: Next 16 App Router, `export async function POST(request: Request, { params }: { params: Promise<{ id: string }> })`. Use relative imports with `.ts` extensions like the existing routes. JSON amounts are 6-dp-max decimal strings (`formatUnits`), times are ISO strings in responses.
- Every dashboard route: `signedInMerchant(request)` first, and every query scoped `WHERE merchant = $1` (another merchant's id → 404, never 403). Public routes return no merchant-private fields.

## Builder A: links + pages (FR-GW-1, FR-GW-2)
Files: `apps/web/db/010_links.sql`, `apps/web/db/011_pages.sql`, `apps/web/lib/server/links.ts`, `apps/web/lib/server/pages.ts`, `apps/web/app/api/v1/links/route.ts` (POST, GET), `apps/web/app/api/v1/links/[id]/cancel/route.ts`, `apps/web/app/api/v1/pages/route.ts` (POST, GET), `apps/web/app/api/v1/public/links/[slug]/route.ts` (GET), `apps/web/app/api/v1/public/links/[slug]/checkout/route.ts` (POST), `apps/web/app/api/v1/public/pages/[slug]/route.ts` (GET), `apps/web/app/api/v1/public/pages/[slug]/checkout/route.ts` (POST), `apps/web/test/gw-links.test.mjs`, `apps/web/test/gw-pages.test.mjs`.
- Link: `POST {amount: "25.00" | null (open amount), currency, description, reference_id?, expires_at?, single_use: bool}` → 201 `{id, slug, url: "/l/<slug>", amount, currency, description, reference_id, single_use, status, expires_at, created_at}`. `reference_id` unique per merchant (409). For fixed amounts in a fiat currency, store the price + currency; convert at checkout time with `createQuote`. Validate the USDT equivalent is within 1..1,000 at checkout (400).
- `GET /api/v1/links` → `{links: [...same + payments (paidCounts)]}` newest first; status computed: cancelled > paid (single-use with a paid checkout) > expired (`expires_at` passed) > active.
- `POST /api/v1/links/{id}/cancel` → `{id, status: "cancelled"}`.
- Public `GET /api/v1/public/links/{slug}` → `{slug, merchant_name, amount, currency, description, status}` (404 unknown).
- Public `POST /api/v1/public/links/{slug}/checkout` (`{amount?}` for open links, form or JSON; rate-limit 20/min per IP): 410 if not active; price → USDT (quote unless USDT/USD); `createSession({merchant (checksummed), merchantName: merchantName(m), amount: usdtUnits, reference: reference_id || slug, items: [{name: description, qty: 1, price: usdtUnits}]})`; `recordCheckout(session.id, "link", link.id, merchant, usdtUnits)`; respond `303` `Location: /checkout/<session.id>` (JSON callers get `{checkout_url, session_id}` with 200 if `accept: application/json`). A single-use link that already has an unpaid open checkout may create another (payment decides); after one is paid it is 410.
- Export `markLinkPaid(sessionId)`: if the session's checkout is a single-use link, nothing else needed (status is computed from paid checkouts); keep it as a no-op-safe function the lane's events.ts calls, returning `{kind, refId} | null`.
- Pages: `POST {title, description?, logo_url? (https), color? (#RRGGBB), currency, items: [{name, price: "12.00"}] (1..20, names unique) | open_amount: {min?, max?}}` → 201 `{id, slug, url: "/p/<slug>", …}`; `GET` list with payments counts. Public `GET /api/v1/public/pages/{slug}` → render info (title, description, logo_url, color, currency, items or open_amount, merchant_name). Public `POST …/checkout {items: [{name, qty}]}` or `{amount}`: prices only from the stored page; unknown item, duplicate, qty < 1 or > 100 → 400; total → USDT (quote unless USDT/USD) within 1..1,000; createSession with the line items; `recordCheckout(…, "page", page.id, …)`; 303 like links.
- Tests: auth (401 without cookie, other merchant's id → 404), validation, status rules, single-use flip after `markCheckoutPaid`, checkout creates a session + checkout row with the right USDT units, prices never from the request, fiat link uses the quote (mock `createQuote` via `fetch` mock of Frankfurter or by using USD/USDT in most tests).

## Builder B: vouchers + webhooks (FR-GW-12, FR-GW-7)
Files: `apps/web/db/020_vouchers.sql`, `apps/web/db/030_webhooks.sql`, `apps/web/lib/server/vouchers.ts`, `apps/web/lib/server/webhooks.ts`, `apps/web/app/api/v1/vouchers/route.ts` (POST, GET), `apps/web/app/api/v1/vouchers/[id]/deactivate/route.ts`, `apps/web/app/api/v1/webhooks/route.ts` (POST, GET), `apps/web/app/api/v1/webhooks/[id]/route.ts` (DELETE), `apps/web/app/api/v1/webhooks/[id]/test/route.ts`, `apps/web/app/api/v1/webhooks/deliveries/[id]/replay/route.ts`, `apps/web/app/api/v1/webhooks/dispatch/route.ts`, `apps/web/test/gw-vouchers.test.mjs`, `apps/web/test/gw-webhooks.test.mjs`.
- Vouchers: `POST {code (3..32, [A-Z0-9_-], stored uppercase, unique per merchant → 409), kind: "percent"|"fixed", value ("10" percent 1..100 integer, or USDT amount "5.00"), expires_at, max_redemptions (1..100000), min_amount?}` → 201 `{id, code, kind, value, expires_at, max_redemptions, times_redeemed: 0, min_amount, active: true, arkiv_entity_key}`. `GET` list newest first. `POST /{id}/deactivate`.
- Arkiv mirror on create (FR-GW-12, FR-ARK-4): one entity with attributes `type = "mcplus.voucher.v1"`, `merchant` (lowercase), `code_hash = hex HMAC-SHA256(VOUCHER_HASH_SECRET, merchant + ":" + CODE)`, `kind`, `value`, `expires_at`; expiration = the voucher's expiry; never the plain code. Read `lib/arkiv.ts`, `scripts/arkiv-probe.ts` and ARCHITECTURE §5 for the SDK calls (`@arkiv-network/sdk` 1.0.1; check its README in node_modules for the exact create API). If `VOUCHER_HASH_SECRET` or the Arkiv env is missing, or the write fails: create the voucher anyway with `arkiv_entity_key = null` and log only `redactArkivError(...)`. Put the Arkiv call behind a function you can mock in tests.
- Redemptions: `applyVoucher(merchant, code, sessionId, usdtAmount: bigint)` → `{ok: true, discount: bigint, usdtAmount: bigint}` | `{ok: false, reason}`. It refuses when `checkoutOf(sessionId)` is null or belongs to another merchant ("Vouchers work on payment links and pages only."), when inactive/expired/used up/below min_amount, or when the discounted total < 1 USDT. It records a reserved redemption `(voucher_id, session_id)` unique per session (re-applying replaces). `confirmRedemption(sessionId)` → atomically `UPDATE app_gw_vouchers SET times_redeemed = times_redeemed + 1 WHERE id = $1 AND times_redeemed < max_redemptions RETURNING …` and marks the redemption confirmed; idempotent per session (second call: no change); returns `{voucherId, code} | null`. Test the race: two sessions confirming the last use → exactly one succeeds.
- Webhooks: `POST {url}` (`httpsUrl`; reject localhost, `.local`, and any host whose DNS answers (A and AAAA, via `node:dns/promises` `lookup(host, {all: true})`) fall in private, loopback, link-local, CGNAT or unique-local ranges; max 5 endpoints per merchant) → 201 `{id, url, secret: "whsec_<32 bytes base64url>", created_at}` (secret once; store it, it signs). `GET` → `{webhooks: [{id, url, created_at, deliveries: [last 20: {id, event, status: "pending"|"succeeded"|"failed", attempts, next_attempt_at, response_status, at}]}]}`. `DELETE /{id}`.
- `enqueueEvent(merchant, type: "payment.succeeded"|"payment.refunded", data: object)`: one delivery row per endpoint of that merchant, body `{id: "evt_…", type, created: unix seconds, data}` stored once (the same body on every retry, re-signed with a fresh t); then `attemptDelivery` inline for each. `attemptDelivery`: re-check the DNS rule, POST with headers `content-type: application/json`, `MC-Signature: t=<unix s>,v1=<hex HMAC-SHA256(secret, t + "." + body)>`, `redirect: "manual"`, 5 s timeout; 2xx → succeeded; else attempts + 1 and `next_attempt_at` = now + 1 min / 5 min / 30 min after attempts 1/2/3, failed after the 4th attempt. Never log the secret or the response body. If `packages/sdk/index.ts` exists on this branch, import `signWebhook` and `SIGNATURE_HEADER` from it; otherwise implement the same format locally and add a test vector.
- `dispatchDue()` processes pending deliveries whose `next_attempt_at <= now` (limit 50). Route `POST /api/v1/webhooks/dispatch` requires `authorization: Bearer <CRON_SECRET>` (constant-time; 401 otherwise; 503 if unset). `POST /api/v1/webhooks/{id}/test` sends a `payment.succeeded` test event with `data: {test: true}` to that endpoint only. `POST /api/v1/webhooks/deliveries/{id}/replay` re-sends one delivery now (owner only).
- Tests: auth/scoping, SSRF rejections (mock `lookup`), signature verifies with an independent HMAC computed in the test, retry schedule, dispatch auth, voucher rules, the redemption race, Arkiv failure path.

## Builder C: reports + settlements (FR-GW-9, FR-GW-10)
Files: `apps/web/lib/server/reports.ts`, `apps/web/lib/server/settlements.ts`, `apps/web/app/api/v1/reports/route.ts`, `apps/web/app/api/v1/reports.csv/route.ts`, `apps/web/app/api/v1/settlements/route.ts`, `apps/web/test/gw-reports.test.mjs`, `apps/web/test/gw-settlements.test.mjs`. No SQL: everything comes from the chain (ARCHITECTURE §1/§4b; AT-15 "match the chain").
- Source: `Paid(paymentId indexed, merchant indexed, payer indexed, invoiceId, orderRef, gross, fee, toInvestors, toMerchant)` and `Refunded(paymentId indexed, amount, totalRefunded)` logs of `payConfig().merchantPay`, from Blockscout's `/api?module=logs&action=getLogs` (read `lib/onchain.ts`: reuse `paidLogs` and its fetch pattern; Refunded is not indexed by merchant, so fetch Refunded logs for the contract and keep the merchant's paymentIds; paginate past 1,000 if simple, else note the ceiling with a `ponytail:` comment). Block time from the log's `timeStamp`.
- `GET /api/v1/reports?from=YYYY-MM-DD&to=YYYY-MM-DD` (UTC days, inclusive; default the last 7 days; max 92 days) → `{from, to, days: [{date, gross, fees, net, refunds, count}] (every day in range, zeros included), totals: {gross, fees, net, refunds, count}, kpis: {newPayers, returningPayers}}` where net = toMerchant + toInvestors (what the merchant's business got before refunds; fees = fee), refunds = sum of Refunded.amount in range; a payer is "returning" if it paid this merchant before the range start. Amounts are decimal strings (`formatUnits(x, 6)`).
- `GET /api/v1/reports.csv?from=&to=` → `text/csv` with a header row; one row per payment: `payment_id,created_utc,currency,gross,fee,to_investors,net,refunded,payer,tx_hash` (currency `USDT`); `content-disposition: attachment; filename="payments-<from>-<to>.csv"`; escape nothing user-controlled is in it, but quote fields anyway.
- `GET /api/v1/settlements?from=&to=` → `{balance: "<merchant wallet USDT>", settlements: [{payment_id, gross, fee, to_investors, net, tx_hash, settled_at (ISO, block time), explorer_url}]}` newest first (T+0: settled in the payment tx). Balance via a USDT `balanceOf` read (see how `lib/onchain.ts` reads the chain; reuse its client).
- All three require `signedInMerchant`; 503 if `payConfig()` is missing.
- Tests: mock `fetch` for Blockscout with a handful of logs (two days, a refund, a returning payer, another merchant's log that must not appear), check day bucketing at UTC midnight, totals, CSV rows, auth, range validation.
